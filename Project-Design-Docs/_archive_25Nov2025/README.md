# Project Design Documentation

This folder contains all design documents for the 3-body project, organized into the following structure:

## Folder Structure

### `/OVERVIEW/`
Contains high-level overview documents, general project plans, and theoretical frameworks that apply across multiple work packages:

- `AMENDED_KS-Symplectic-Reduction-Conjectural-Statement.md` - Amended theoretical framework for KS symplectic reduction
- `AMENDED_SUMMARY.md` - Executive summary of AMENDED documentation changes
- `AMENDED_Updated-Plan-WP2-5-Nov2025.md` - Amended overall project plan for Work Packages 2-5
- `KS-Symplectic-Reduction-Conjectural-Statement.md` - Original theoretical framework
- `Previous Overview...md` - Previous project overview document
- `Updated Plan -- 3-Body WP2-5 Nov2025.md` - Overall project plan for Work Packages 2-5

### `/Implementation-Status/`
Contains implementation progress tracking and status documents, renamed with descriptive prefixes:

- `Time-Regularization-Final-Status.md` - Final implementation status for time regularization integration
- `Time-Regularization-Implementation-Action-Plan.md` - Action plan for time regularization implementation
- `Time-Regularization-Implementation-Status.md` - Current implementation status tracking
- `Time-Regularization-Implementation-Summary.md` - Summary of time regularization implementation

### `/WP1/` - `/WP5/`
Work Package-specific folders containing detailed design documents, implementation plans, and task-specific documentation. Each WP folder contains:

- Implementation plans for specific tasks (e.g., `Task-2.1.1-Implementation-Plan.md`)
- Part-specific designs (e.g., `Task-2.1.1-Part-A-Design.md`)
- AMENDED versions of implementation plans with updated approaches
- WP-specific summaries and status documents

#### Notable WP2 Files:
- `AMENDED_WP2.2-S1-Lift-Implementation-Plan.md` - S¹ lift implementation with amendments
- `AMENDED_WP2.3-KS-Spinor-Lift-Time-Regularization-Focus.md` - KS spinor lift focusing on time regularization
- `AMENDED_WP2.3-KS-Spinor-Lift-Constraint-Handling-Focus.md` - KS spinor lift focusing on constraint handling

## Document Naming Conventions

- **AMENDED_** prefix: Documents that have been revised with significant updates or corrections
- **WP[N].[M]** format: Work Package N, task M specific documents
- **Task-[N].[M].[P]** format: Specific task implementations within work packages
- **Part-[X]** suffix: Subsections of larger implementation plans

## Navigation

- For project overview and theory: Start with `/OVERVIEW/`
- For implementation progress: Check `/Implementation-Status/`
- For specific work package details: Navigate to respective `/WP[N]/` folder
